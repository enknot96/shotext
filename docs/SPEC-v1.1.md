# ShoText！ v1.1 仕様書（ブラッシュアップ）

- ステータス: **ドラフト（未承認）**
- 対象: `packages/core` / `packages/local-ocr`
- 現行バージョン: 1.0.1 → 目標: 1.1.0

## 1. 目的

「動画を止めて、画面に写っている文字を囲んで、コピペする」という体験はそのままに、**どんな画面でもきれいに取れる・失敗しても迷わない**状態にする。あわせて英語圏ユーザーでも違和感なく使えるようにする。

## 2. 受入条件（Definition of Done）

1. 英語の複数行テキストが、単語の間にスペースを入れて連結される（`Hello` + `world` → `Hello world`）
2. コードを読み取ったとき、改行が保持される。インデントも可能な範囲で再現される
3. ダークテーマ（黒背景に明るい文字）のエディタ画面でも、ライトテーマと同程度に読み取れる
4. ターミナル画面では、行頭のプロンプト記号（`$` など）が除去される
5. 範囲選択後、完了まで「処理中」の表示が出る
6. OCR失敗、結果が空、撮影不可のページ、小さすぎる選択のいずれでも、**必ず何らかの表示が出る**（無反応をなくす）
7. インストール前から開いていたタブでも、ページを再読み込みせずに動く
8. コピー後にトーストから編集パネルを開き、テキストの編集、整形タイプの切り替え、再コピーができる
9. 拡張機能のUIの文言がすべて英語（短く平易な表現）になっている
10. ブラウザの言語が日本語なら `jpn+eng`、それ以外なら `eng` でOCRする
11. `core` の純粋関数（判定・整形）に自動テストがあり、すべて通る

## 3. 非目標（今回やらないこと）

- ライブ写経モード（動いている動画を自動で追いかけるOCR）
- AIエンジン（Claude Vision など外部APIを使うOCR）
- 履歴やノートの機能、サイドパネル
- i18n（表示言語の自動切り替え）、拡張機能名の変更
- 設定画面（options ページ）
- 右クリックメニューやポップアップからの起動ボタン（次回以降の候補）
- 前後の文脈から判断する誤認識補正（`l/1/I`、`O/0` など。誤った補正をするリスクが高いため）
- 日本語・英語以外の言語への対応

## 4. 仕様詳細

### 4.1 画像の前処理（offscreen、切り抜き後に実施）

| 処理 | 仕様 | 初期値（実装時に調整） |
|---|---|---|
| 拡大 | 切り抜いた画像を拡大してからOCRする。上限画素数を超える場合は倍率を下げる | 倍率2倍、上限約400万画素 |
| グレースケール化 | 輝度に変換する | — |
| 暗い背景の反転 | 平均輝度がしきい値未満なら、白黒を反転して「白背景に黒文字」にそろえる | しきい値128 |
| 二値化 | **独自処理は入れず、Tesseract内部の処理に任せる**。検証で効果が確認できた場合のみ採用する | — |

### 4.2 整形タイプの自動判定

OCR結果の生テキストを `prose`（文章）、`code`（コード）、`terminal`（ターミナル）の3種類に判定する。スコアで判定し、誤判定は編集パネルで切り替えて直せる前提とする。

- **terminal**: 空でない行の半数以上が、プロンプト記号（`$ ` / `% ` / `> ` / `PS ...>`）で始まる
- **code**: 次の特徴を点数化し、しきい値以上ならコードとする
  - 行末の記号: `{` `}` `;` `)` `:` `,`
  - 行頭のインデント
  - 記号の割合
  - 主要キーワード: `const` / `let` / `function` / `def` / `import` / `return` / `class` / `if` / `for` / `=>` など
- **prose**: 上のどちらにも当てはまらない場合

### 4.3 タイプ別の整形ルール

**共通（全タイプ）**

- 全角英数字・全角記号（U+FF01〜FF5E）を半角に変換する。ただし `prose` で前後が日本語の場合は変換しない
- スマートクオート（`“ ” ‘ ’`）を `" '` に変換する（`prose` で日本語の文中にある場合は除く）
- 日本語の文字と文字の間に入った余分なスペースを除去する

**prose（文章）**

- 見た目上の折り返し改行を連結する。文末記号で終わる行と空行は、改行として残す（現行ロジックを踏襲）
- 連結の境目の左右がどちらも英数字なら、**スペースを挟む**。日本語が絡む場合は挟まない
- 行末のハイフンで分かれた単語を結合する（`recog-` + `nition` → `recognition`。両側が英小文字の場合のみ）

**code（コード）**

- 改行は保持し、連結しない
- インデントは、各行の左端のx座標と平均文字幅から推定し、スペースで再現する（※要確認A）
- エディタの行番号を除去する。**8割以上の行**が連番の整数で始まる場合のみ除去し、誤って消すことを避ける

**terminal（ターミナル）**

- 行頭のプロンプト記号（`$ ` / `% ` / `> ` / `PS ...> `）を除去する
- プロンプトのない行（コマンドの出力）はそのまま残す

### 4.4 OCRの言語

- `chrome.i18n.getUILanguage()` が `ja` で始まれば `jpn+eng`、それ以外は `eng` にする
- 必要な学習データだけを読み込む（英語環境では jpn の約2MB を読み込まない）

### 4.5 コピーの挙動と編集パネル

- **選択したらすぐコピーする挙動は維持する**
- トーストの表示
  - 処理中: `Reading…`
  - 完了: `Copied!` と結果の冒頭（約30文字）、`Edit` ボタン
  - 表示時間は約4秒。マウスを乗せている間は消えない
- `Edit` を押すと、選択範囲の近くに編集パネルを開く（画面外にはみ出さないよう位置を補正する）
  - テキスト欄（編集できる）
  - 整形タイプの切り替え: `Text` / `Code` / `Terminal`。**生テキストから整形し直す**ため、手で編集した内容は切り替え時に破棄される
  - `Copy` ボタン（`Ctrl/Cmd+Enter` でも実行）
  - 閉じる: `×` ボタン、`Esc`、パネルの外をクリック
- トーストと編集パネルは **Shadow DOM** の中に描画し、ページ側のCSSの影響を受けないようにする
- 保持する結果は直近の1件のみ（生テキスト、判定タイプ、選択範囲）。タブ内のメモリにだけ置き、保存はしない

### 4.6 無反応をなくす（エラー処理）

| ケース | 挙動 | 表示文言（案） |
|---|---|---|
| OCRが例外を出す | トーストで通知する | `Couldn't read text` |
| 結果が空 | トーストで通知する。**クリップボードは上書きしない** | `No text found` |
| 選択が小さすぎる（幅か高さが8px未満） | OCRせずに終了する | `Selection too small` |
| 撮影できないページ（`chrome://`、Web Store など） | Chromeの通知を出す | `Can't capture this page` |
| 処理中にタブが切り替わった | Chromeの通知を出す（現行の文言を英語化し、旧名「スクショOCR」も修正） | `Tab changed. Please try again.` |
| クリップボードへの書き込みに失敗 | 編集パネルを開き、テキストを全選択した状態にする | `Press Ctrl+C to copy` |

### 4.7 スクリプトの注入方式

- `manifest.json` の静的な `content_scripts`（`<all_urls>`）をやめる
- ショートカットが押されたときに、`chrome.scripting.executeScript` でアクティブなタブへ注入する。`scripting` 権限を追加する
- 注入の重複を防ぐガードを入れる（2回目以降は注入を省略する）
- `activeTabId` を service worker のグローバル変数に持たず、メッセージの `sender.tab.id` で受け渡す（service worker が停止しても状態が消えないようにする）
- `web_accessible_resources` が不要になるかを確認し、不要なら削除する（※要確認B）
- 全画面表示の動画の上でも選択できるよう、オーバーレイは `document.fullscreenElement ?? document.body` に追加する（※要確認C）

### 4.8 UIの文言（英語のみ、短く平易に）

| 場所 | 文言（案） |
|---|---|
| manifest の `description` | `Select an area on screen and copy its text (OCR).` |
| commands の `description` | `Select an area to copy text` |
| ポップアップ | `Press Alt+Shift+D, then drag over text. It's copied automatically.` と `Change shortcut` リンク（`chrome://extensions/shortcuts` を開く） |
| トーストと編集パネル | 4.5・4.6 のとおり |

## 5. 例外・境界ケース

- 高DPIのディスプレイ（`devicePixelRatio` が 1.5 や 2 など）での切り抜き位置のずれ
- ページをスクロールした状態、ズームを変えた状態での選択
- 日本語と英語が混ざった1行（`Reactのコンポーネント` など）でのスペースの扱い
- 空行だけの結果、記号だけの結果
- 行番号付きのエディタで、行番号が1桁から2桁に変わる箇所
- CSSの影響が強いサイト（YouTube、GitHub）での編集パネルの表示崩れ
- PDFビューアのタブ（撮影できるかどうかは実機で確認）

## 6. テスト方針

- **自動テスト**: `packages/core` に vitest を導入し、次を対象にする
  - タイプ判定（prose / code / terminal の代表例と、境界の例）
  - 整形（英語の連結、ハイフン結合、日本語の空白除去、全角→半角、行番号除去、プロンプト除去）
- **手動テスト**（チェックリストを作成する）
  - YouTube: ダークテーマのコード、ライトテーマのコード、英文のプロンプト、和文のプロンプト、ターミナル、全画面表示
  - インストール前から開いていたタブ、`chrome://` ページ、小さすぎる選択、文字のない領域
  - 編集パネル: 表示、タイプ切り替え、再コピー、Esc
  - ブラウザの言語が英語の場合と日本語の場合のOCR言語
- 前処理のパラメータ（倍率、しきい値）は、手元のスクリーンショットで目視比較して決める（数値の計測は行わない）

## 7. 互換性・移行

- 権限の変更: `scripting` を追加し、静的なコンテンツスクリプトの `<all_urls>` を削除する
  - 更新時に権限の再承認ダイアログが出ないか要確認（※要確認D）
- ストレージや設定の持ち越しは無い（もともと保存するデータが無いため）
- ショートカット `Alt+Shift+D` は変更しない

## 8. ロールバック

- Chrome Web Store には過去版に戻す機能が無いため、問題が出た場合は **1.0.1 の内容を 1.1.1 として再提出**する
- 変更は機能単位でコミットし、個別に revert できるようにする

## 9. 要確認事項の調査結果

- **A（確認済み）**: `worker.recognize(image, {}, { blocks: true })` で `data.blocks → paragraphs → lines → words` の構造が得られ、各要素に `bbox {x0, y0, x1, y1}` が付いている（tesseract.js 7.0.0 の `src/index.d.ts` で確認）。インデントの推定に使える
- **B（確認済み）**: 公式ドキュメントに「拡張機能のオリジンから読み込まれたページやスクリプトは、その拡張機能のリソースにアクセスできる」とある（Chrome公式 manifest/web-accessible-resources）。offscreen document は拡張機能のオリジンなので**不要**。削除したうえで、手動テストで動作を確認する
- **C（未確認・実機で確認）**: 公式ドキュメントには記載が無い。手動テストで確認し、問題があれば全画面対応は非目標に移す
- **D（確認済み）**: `scripting` と `activeTab` はどちらも権限の警告が**出ない**（Chrome公式 permissions-list）。再承認が必要になり拡張機能が無効化されるのは「警告が出る権限を追加した場合」のみ（Chrome公式 permission-warnings）。したがって今回の更新では無効化されない
- **補足（確認済み）**:
  - `activeTab` は「commands API のキーボードショートカットの実行」でも付与され、`scripting` 権限があれば `scripting.executeScript()` を実行できる（Chrome公式 activeTab）
  - `tabs.captureVisibleTab` は `<all_urls>` か `activeTab` のどちらかがあれば呼べる（Chrome公式 tabs API）。静的な `<all_urls>` コンテンツスクリプトをやめても撮影は動く
  - コンテンツスクリプトの `<all_urls>` が無くなることで、インストール時の広範なアクセス権限の警告が無くなる見込み（実機で確認する）
